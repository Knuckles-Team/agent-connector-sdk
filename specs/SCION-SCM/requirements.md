# SCION-SCM requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A child row `.n` is one five-minute unit of work.
A row names the file it touches and the test that proves it. The generator
sets each row's state in `status.json`.

| ID | Requirement | Verification |
|---|---|---|
| `SCION-SCM-R001` | **Source client.** The SDK provides one typed client for the served `source.*` operations. It covers tree, blob, diff, history, blame, commit, land, and revert. A local bounded blob cache keyed by content digest backs blob reads. The connector or host composes the client; the SDK serves nothing itself. | Child rows R001.1 through R001.6 bind; `tests/test_source_client_served.py` proves the served path. |
| `SCION-SCM-R001.1` | **Model.** The client exposes one frozen typed method per `source.*` operation. A request binds repository identity, revision or branch reference, a path prefix where the operation takes one, and typed parameters. A result is a typed page or receipt with a stable continuation token. No method accepts or returns an untyped payload. | `tests/test_source_client.py::test_request_and_page_models_are_typed_and_frozen` |
| `SCION-SCM-R001.2` | **Behavior.** Read operations return bounded pages with continuations. A blob read consults the local cache first and serves cached bytes only while the stored digest matches. A write submits through its operation with one stable operation identity per logical change. An identical retry reuses that identity and returns the same receipt. The cache is bounded by entry count and byte count and evicts least-recently-used entries. | `tests/test_source_client.py::test_cache_is_bounded_and_digest_checked` and `tests/test_source_client.py::test_retry_reuses_operation_identity` |
| `SCION-SCM-R001.3` | **Wiring.** The repository-manager connector composes the client behind its served development tools inside arbora MCP. A host may compose the same client directly. The client is a planned new module under `agent_connector_sdk/`. The connector's served operations build it with the authenticated caller and the served endpoint. They reach the SDK through `register_tool_surface` at `agent_connector_sdk/mcp/tool_surface.py:305` and `dispatch_async` at `agent_connector_sdk/mcp/action_dispatch.py:196`. The SDK owns no serving, registry, or admission code. | `tests/test_source_client_served.py::test_connector_tool_composes_the_client` |
| `SCION-SCM-R001.4` | **Refusal.** A refused or failed operation returns a typed refusal with a closed reason code: `unauthorized`, `not_found`, `conflict`, `path_denied`, `oversized`, `deadline_exceeded`, `transport_unavailable`. A refused write produces no effect and advances no revision. A cache read whose digest does not match evicts the entry and re-reads through the served operation. | `tests/test_source_client.py::test_refusals_are_typed_and_zero_effect` |
| `SCION-SCM-R001.5` | **Evidence.** Each result binds repository identity, revision, operation identity, request digest, page bounds, and the receipt reference where one exists. Cache events record digest, hit or miss, and eviction count without content. Diagnostics never contain credentials, resolved secret values, or private paths. | `tests/test_source_client.py::test_results_bind_provenance_without_secrets` |
| `SCION-SCM-R001.6` | **Hot-path proof.** The served test enters through a registered repository-manager development tool inside arbora MCP. It calls a `source.*` operation through the SDK client against a controlled served backend. It observes the typed page. A warm and a cold blob read agree on digest and bytes. A conflicting commit returns the stable `conflict` code with zero write effect. | `tests/test_source_client_served.py::test_served_client_pages_and_conflict_refusal` |
| `SCION-SCM-R002` | **Virtual workspace mount.** The SDK provides a FUSE or overlay mount that materializes files on read and records writes as a pending changeset. The mount is sparse by declared path prefix. It performs no repository clone. | Child rows R002.1 through R002.6 bind; `tests/test_source_mount_served.py` proves the served path. |
| `SCION-SCM-R002.1` | **Model.** The mount exposes a directory tree over the source client for declared path prefixes only. An entry carries path, mode, and blob digest. Mount state binds repository identity, base revision, prefix set, and pending changeset identity. A write produces one pending changeset entry with path, operation, and new blob reference. | `tests/test_source_mount.py::test_mount_state_and_entry_models_are_typed` |
| `SCION-SCM-R002.2` | **Behavior.** Directory entries resolve lazily from the served tree operation. A file read materializes content through the client's blob path, using the local cache where the digest matches. A write appends one entry to the pending changeset and never mutates the mounted revision. A repeated write to one path replaces the earlier entry. A flush submits the pending changeset as one commit through the client. | `tests/test_source_mount.py::test_reads_materialize_and_writes_accumulate` |
| `SCION-SCM-R002.3` | **Wiring.** The mount is a planned new module under `agent_connector_sdk/`. The connector or host composes it for tools that need files on a filesystem. FUSE is the default backend on hosts that provide it; an overlay copy-up backend covers hosts without FUSE. The SDK keeps no clone, object database, or full checkout behind the mount. | `tests/test_source_mount.py::test_mount_composes_the_source_client` |
| `SCION-SCM-R002.4` | **Refusal.** The mount refuses to start without an admitted source client or with an unknown prefix. Path traversal and symlink escape outside the mount root refuse on every read and write. A flush whose base revision has changed returns the stable `conflict` code. A failed flush leaves the pending changeset intact and visible. | `tests/test_source_mount.py::test_refusals_preserve_pending_changeset` |
| `SCION-SCM-R002.5` | **Evidence.** Mount events record repository identity, base revision, prefix set, read count, cache hit count, and pending changeset digest. A flush event binds the commit receipt and per-path outcomes. Diagnostics exclude credentials and private absolute paths. | `tests/test_source_mount.py::test_mount_events_bind_receipts_without_secrets` |
| `SCION-SCM-R002.6` | **Hot-path proof.** The served test mounts the workspace over the source client against a controlled served `source.*` backend. Reads return exact bytes for declared prefixes and refuse outside them. A write followed by a flush submits exactly one changeset. A second flush after a conflicting change returns `conflict` and keeps the pending changeset intact. | `tests/test_source_mount_served.py::test_served_mount_read_write_and_conflicting_flush` |
