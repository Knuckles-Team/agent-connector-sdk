# SCION-REPOSITORY-TRANSPORT requirements

| ID | Requirement | Verification |
|---|---|---|
| `SCION-REPOSITORY-TRANSPORT-R001` | **Repository transport hydrates code and specification sources from Git.** The SDK fetches an authenticated, immutable repository revision and pages its file blobs and tombstones to the graph service's generated IndexRepository operation, letting a contributor hydrate both code and specification sources from their own Git provider without the SDK inventing symbol or semantic identity itself. | Integration tests using a local Git fixture that submit a revision through IndexRepository and confirm the graph service, not the SDK, produces the resulting symbol and specification identities. |
| `SCION-REPOSITORY-TRANSPORT-R002` | **SDK is the sole path for repository-native codebase hydration.** Every connector performs repository-native codebase hydration through scion-sdk. No separate repository-fetching path outside the SDK is maintained in parallel as an alternative implementation of the same capability. | A dependency and import scan across connector repositories confirming repository hydration calls route only through the SDK's transport package. |
| `SCION-REPOSITORY-TRANSPORT-R003` | **Repository ref walk traverses each Git tree once with batched reads.** The repository transport's walk phase visits each distinct Git tree only once and reads objects in batches, using a recursive tree listing and a batched object-read call or an equivalent provider batch API, rather than issuing one call per object, since object-tree traversal is a dominant pre-parse cost on a large repository. | A before/after benchmark on public medium and large repository fixtures with cold and warm caches, reporting clone, fetch, walk, and submit timings separately and confirming output and refusal semantics are unchanged. |
| `SCION-REPOSITORY-TRANSPORT-R004` | **Repository transport submits bounded, outcome-complete index batches.** The repository transport authenticates before fetching, pages file blobs and tombstones within the default batch-size bounds, and submits each batch to the graph service's IndexRepository operation with a per-file outcome, so no blob is silently skipped and a batch is accepted only when requested and returned identity, path set, outcomes, and digest all agree. | Tests against synthetic Git fixtures asserting a too-large file or missing per-file outcome is refused and an oversized or misaligned batch cannot produce a complete indexing receipt. |
| `SCION-REPOSITORY-TRANSPORT-R005` | **Branch-aware transport batches indexing into one call per batch.** Repository ingestion submits one batched IndexRepository call per bounded batch of files rather than issuing a separate round trip for each file, eliminating a per-file request loop as the dominant network cost of a large-repository ingest. | A test asserting the number of IndexRepository calls scales with the number of batches, not the number of files, for a repository fixture exceeding one batch size. |
| `SCION-REPOSITORY-TRANSPORT-R006` | **Provider pages respect their requested bound.** Count snapshot files and tombstones together. Each count must fit the requested size. Tree entries must also fit the requested size. The SDK refuses an oversized page before processing its contents. A failed later page does not undo batches already submitted. | Tests reject oversized pages from both provider ports. No entry from a refused snapshot page reaches the graph. |
| `SCION-REPOSITORY-TRANSPORT-R007` | **Local Git blob reads stay within the selected revision.** The local provider binds its repository and provider identity to the request. It verifies the immutable commit resolves to the requested tree. It fetches only immutable blob IDs listed in that tree. Missing or mismatched identities refuse before blob read. | A local Git fixture requests a listed blob, an unreferenced blob, and a tree from another commit. Only the listed blob is returned. |
