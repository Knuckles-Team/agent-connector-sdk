# SDK-SOURCE-INGEST — SDK source sync, drift quarantine, and adapter migration

**Requirement IDs:** SDK-SOURCE-INGEST-R001, SDK-SOURCE-INGEST-R002, SDK-SOURCE-INGEST-R003, SDK-SOURCE-INGEST-R004, SDK-SOURCE-INGEST-R005, SDK-SOURCE-INGEST-R006, SDK-SOURCE-INGEST-R007, SDK-SOURCE-INGEST-R008, SDK-SOURCE-INGEST-R009.
**Owner:** agent-connector-sdk.

## Outcome and authority

One SDK runner discovers certified sources, extracts bounded pages, classifies contract drift, and submits them through the graph service's generated `SourceIngest` client. The graph service alone commits data, stores checkpoints, renders candidate graph schemas, and activates repairs. The SDK does not maintain a competing cursor or semantic store. Source adapters for enterprise systems, documents, sessions, feeds, and vendor enrichment all use this same lifecycle.

## Architecture

```text
certified manifest → runner supervisor → SourceAdapter.discover/extract
                            │                    │
                            └→ drift classifier ◀┘
                                  │ compatible     └ incompatible → quarantine/report
                                  ▼
                          generated SourceIngest operation
                                  │ durable receipt/checkpoint
                                  └→ next page or retry
```

`SourceAdapter.describe()` is pure; `discover(session)` validates the live source contract; `extract(session, SourceCheckpoint | None)` returns one bounded `RecordPage`; `reconcile(session, known_ids)` reports deletions. `runner/`, `manifest/presets.py`, `ports/source_adapter.py`, and `sinks/` are the extension points. A connector preset declares endpoint and auth references, resource scope, update mode, schema identity, paging bound, and source capability. Provider-specific API logic lives in adapters; universal scheduling, retries, health, and progress live in the runner.

The runner reads the durable checkpoint through the generated client at the start of each stream and after ambiguous replies. It advances only on an accepted durable receipt that matches tenant, source identity, stream, manifest digest, and expected checkpoint. Timeouts, partial pages, failed validation, and schema drift never advance it. Duplicate delivery is safe through a stable source/page idempotency key. Work remains bounded by records, bytes, concurrency, retry budget, and rate limits.

The drift classifier compares normalized prior and current field types, requiredness, enum domains, object nesting, identifier semantics, and declared evolution policy. It emits `SchemaDriftReport` with source/stream/tenant, old/new schema digests, affected fields, classification (`COMPATIBLE`, `REQUIRES_REVIEW`, `BREAKING`), observed sample digest, and reason codes. Unknown or breaking changes quarantine the page before submission. A proposed repair may be generated by a decision service, but only a graph-service candidate schema/pack, validation on representative instances, shadow ingest, and explicit approval can activate it. The SDK records the proposal and pauses the stream; it never mutates graph schema directly.

The migration target includes enterprise source sync, external graph/GraphQL/event/OCEL adapters, data prep and connection profiling (SDK-SOURCE-INGEST-R004). Document, session, feed, repository-related source transport and non-model readers (SDK-SOURCE-INGEST-R005). Vendor enrichment extractors as adapter presets and governed write-back transport (SDK-SOURCE-INGEST-R006). Operational event feeds use the same SourceAdapter contract, with each feed package owning its provider API code. Port reusable behavior into SDK modules. Delete old duplicate paths in their owning repositories only when parity evidence exists. Never migrate model inference or semantic graph derivation into the SDK. For SDK-SOURCE-INGEST-R003 and SDK-SOURCE-INGEST-R007, SDK owns classification and proposal transport. Graph-owned schema construction, shadow validation, and activation remain outside this repository.

Two source-adapter families extend this same contract. Adapters for GBIF and iNaturalist occurrence records, NOAA GHCN/ISD and Open-Meteo weather data, and NOAA storm events produce typed `OrganismObservation`, `WeatherObservation`, and `WeatherEvent` records, with weather stations represented as a `Place` located in a `Region` (SDK-SOURCE-INGEST-R008). A taxonomy connector ingests NCBI Taxonomy and GBIF backbone taxa as `kg:Taxon` individuals carrying rank, parent, scientific name, NCBI and GBIF identifiers, and a term CURIE, validated against the `world_model-v1` `TaxonShape`, with bounded delta synchronization (SDK-SOURCE-INGEST-R009). Both families use the same discover/extract/reconcile adapter lifecycle, checkpointing, and drift quarantine as every other source.

## Fresh-checkout development

`uv sync` installs the package. Contributors implement `SourceAdapter` against the public protocol and test with an in-memory fake `McpSession` and generated-client fake. Fixtures use synthetic tenants and data. `uv run --frozen python -m pytest -q tests` and repository hooks exercise the unit path without network, credentials, or a live graph. A contributor-owned graph service is needed only for the final durable-receipt acceptance probe.

## Live meeting transcript and summary transport (SDK-SOURCE-INGEST-R014; WEBUI:10)

Source: open-source-libraries/meetily/README.md. Original record SHA-256: c82a815c87428a5baf4379ef7790bafb24a5d3367d16ebd85a6c39ff9b52521d. WebUI consumer: WEBUI-APPS-R001.5. The source acceptance and record remain unchanged.

The current WebUI records with MediaRecorder. It stops and posts to /api/enhanced/voice/transcribe. This is single-shot dictation. Preserve that behavior.

The registered audio producer is the audio-transcriber repository tool transcribe_audio. The MCP server registers it for one file or microphone capture. It has no meeting-segment or summary-provider contract. The SDK must not claim that it provides live transcripts. Owners must identify any meeting-specific operation before implementation.

Each transcript binds meeting, tenant, segment, sequence, correction revision, source time, lifecycle, and source/model provenance. Accept bounded ordered segments while partial. An exact replay with the same meeting, sequence, revision, and payload digest returns its existing receipt without another effect. A different payload at that binding refuses. A correction advances one segment to a newer revision. It invalidates summaries for older transcript revisions. Gaps may remain pending during partial ingestion. They block finalization and summary dispatch until filled. Stale updates refuse.

Summaries bind to the finalized transcript and selected provider/model revisions. Capture and egress admission precede effects. No summary call occurs before finalization of a complete sequence. An unavailable local provider cannot fall back to hosted.

Flow: WebUI capture -> registered audio operation -> SDK tools/call -> EG transcript/context authority -> GraphOS live updates and selected summaries -> WEBUI-APPS-R001.5. EG and GraphOS owners allocate counterpart IDs. No new meeting operation or provider binding is asserted.
