# SDK source sync, drift quarantine, and adapter migration

**Program IDs:** EH-339, EH-402, EH-403, EH-499, EH-500, EH-501, EH-510.
**Owner:** agent-connector-sdk. **Delivery state:** UNKNOWN. **Acceptance state:** OPEN.

## Outcome and authority

One SDK runner discovers certified sources, extracts bounded pages, classifies contract drift, and submits them through the graph service's generated `SourceIngest` client. The graph service alone commits data, stores checkpoints, renders candidate graph schemas, and activates repairs. The SDK does not maintain a competing cursor or semantic store. Source adapters for enterprise systems, documents, sessions, feeds, and vendor enrichment all use this same lifecycle.

## Architecture

```text
certified manifest → runner supervisor → SourceAdapter.discover/extract
                            │                    │
                            └→ drift classifier ◀┘
                                  │ compatible     └ incompatible → quarantine/report
                                  ▼
                          generated SourceIngest operation
                                  │ durable receipt/checkpoint
                                  └→ next page or retry
```

`SourceAdapter.describe()` is pure; `discover(session)` validates the live source contract; `extract(session, SourceCheckpoint | None)` returns one bounded `RecordPage`; `reconcile(session, known_ids)` reports deletions. `runner/`, `manifest/presets.py`, `ports/source_adapter.py`, and `sinks/` are the extension points. A connector preset declares endpoint and auth references, resource scope, update mode, schema identity, paging bound, and source capability. Provider-specific API logic lives in adapters; universal scheduling, retries, health, and progress live in the runner.

The runner reads the durable checkpoint through the generated client at the start of each stream and after ambiguous replies. It advances only on an accepted durable receipt that matches tenant, source identity, stream, manifest digest, and expected checkpoint. Timeouts, partial pages, failed validation, and schema drift never advance it. Duplicate delivery is safe through a stable source/page idempotency key. Work remains bounded by records, bytes, concurrency, retry budget, and rate limits.

The drift classifier compares normalized prior and current field types, requiredness, enum domains, object nesting, identifier semantics, and declared evolution policy. It emits `SchemaDriftReport` with source/stream/tenant, old/new schema digests, affected fields, classification (`COMPATIBLE`, `REQUIRES_REVIEW`, `BREAKING`), observed sample digest, and reason codes. Unknown or breaking changes quarantine the page before submission. A proposed repair may be generated by a decision service, but only a graph-service candidate schema/pack, validation on representative instances, shadow ingest, and explicit approval can activate it. The SDK records the proposal and pauses the stream; it never mutates graph schema directly.

The migration target includes enterprise source sync, external graph/GraphQL/event/OCEL adapters, data prep and connection profiling (EH-499); document, session, feed, repository-related source transport and non-model readers (EH-500); vendor enrichment extractors as adapter presets and governed write-back transport (EH-501). Operational event feeds use the same SourceAdapter contract, with each feed package owning its provider API code. Port reusable behavior into SDK modules; delete old duplicate paths in their owning repositories only when parity evidence exists. Never migrate model inference or semantic graph derivation into the SDK. For EH-403/510, SDK owns classification and proposal transport; graph-owned schema construction, shadow validation, and activation remain outside this repository.

## Fresh-checkout development

`uv sync` installs the package. Contributors implement `SourceAdapter` against the public protocol and test with an in-memory fake `McpSession` and generated-client fake. Fixtures use synthetic tenants and data. `uv run --frozen python -m pytest -q tests` and repository hooks exercise the unit path without network, credentials, or a live graph. A contributor-owned graph service is needed only for the final durable-receipt acceptance probe.
