# SDK-CONNECTOR-CONTROL requirements

| ID | Requirement | Verification |
|---|---|---|
| `SDK-CONNECTOR-CONTROL-R001` | **ConnectorPackClient uses a deterministic idempotency key.** The SDK's ConnectorPackClient submits pack publication requests through the generated ConnectorPack types and computes a deterministic idempotency key from tenant, connector identity, canonical pack digest, and operation, so repeating an identical request returns the same durable result. | Unit tests that retry an identical publish request after a simulated transport loss and assert the same import operation key is reused, using only the generated wire types for status and import. |
| `SDK-CONNECTOR-CONTROL-R002` | **Contract pin travels as a claim attribute, not recomputed downstream.** The SDK computes the contract pin by normalizing tool input and output schemas through manifest/tool_schema.py and passes it to the graph service as a claim attribute; the graph service stores that value without independently recomputing the SDK's schema normalization. | Conformance tests asserting the pin calculation lives in the SDK and that a stored claim attribute matches the SDK-computed value unchanged. |
| `SDK-CONNECTOR-CONTROL-R003` | **Canonical output-schema digest on every certified tool pin.** Certification computes a normalized output-schema digest for every tool pin alongside the input-schema digest, fingerprinting a missing output schema canonically rather than treating it as an empty wildcard. | A conformance test that certifies a tool with no declared output schema and asserts a canonical, nonempty digest is produced. |
| `SDK-CONNECTOR-CONTROL-R004` | **Contract-pin verification owned by the SDK's own test kit.** The SDK's own conformance test kit computes and checks the contract pin from its tool schema normalization, because that normalization is SDK-specific logic the graph service cannot reproduce independently. | A conformance suite that recomputes the contract pin from a sample manifest and asserts it matches the certified value. |
| `SDK-CONNECTOR-CONTROL-R005` | **Pack publisher and source submission use generated graph-client types.** The SDK's pack publisher uses the graph service's generated ConnectorPack and AgentComponent.Content request and response types instead of a hand-written placeholder content pack, and SQL-backed source record submission uses the generated SourceIngest request and receipt types through the existing sink. | Integration tests that publish a pack and submit a source record through the generated types and assert no placeholder or hand-written duplicate type is used. |
| `SDK-CONNECTOR-CONTROL-R006` | **Decision-service proposals for tool choice and triage stay observational.** Connector-internal tool choice and inbound event triage may request a proposal from a decision service, but that proposal is observational only: it never directly authorizes a side effect or bypasses the deterministic write-back rules. | A contract test that issues a decision-service proposal and asserts no side effect is authorized without passing through the deterministic write-back path. |
| `SDK-CONNECTOR-CONTROL-R007` | **Fleet-wide re-certification yields nonempty schema fingerprints.** Re-certifying the connector fleet means every package produces current, nonempty fingerprints for each declared tool pin and passes a current live-contract comparison; a package count alone is not sufficient evidence of certification. | A certification run across the full connector set asserting every pin's input and output schema fingerprint is nonempty and matches a live contract comparison. |
| `SDK-CONNECTOR-CONTROL-R008` | **Closed, canonical pack annotation map across the connector fleet.** Every connector pack entry carries a closed, canonical annotation map of capability names, input and output schema digests, modality, and bounded cost and latency estimates with units; a missing estimate is recorded as unknown, never zero. | Conformance tests that validate the annotation map's types and units and assert a semantic annotation change shifts the pack digest. |
| `SDK-CONNECTOR-CONTROL-R009` | **Connector batch A-E migrates fully onto the SDK client.** Connector packages in the A-E range import agent_connector_sdk modules for server construction, configuration, exceptions, and transport security in place of their prior agent_utilities imports, and call the generated EG client instead of a local ingestion helper. | A per-package import scan and test run across the A-E batch confirming no agent_utilities import remains and ingestion runs through the EG client. |
| `SDK-CONNECTOR-CONTROL-R010` | **Connector batch F-J migrates fully onto the SDK client.** Connector packages in the F-J range import agent_connector_sdk modules for server construction, configuration, exceptions, and transport security in place of their prior agent_utilities imports, and call the generated EG client instead of a local ingestion helper. | A per-package import scan and test run across the F-J batch confirming no agent_utilities import remains and ingestion runs through the EG client. |
| `SDK-CONNECTOR-CONTROL-R011` | **Connector batch K-O migrates fully onto the SDK client.** Connector packages in the K-O range import agent_connector_sdk modules for server construction, configuration, exceptions, and transport security in place of their prior agent_utilities imports, and call the generated EG client instead of a local ingestion helper. | A per-package import scan and test run across the K-O batch confirming no agent_utilities import remains and ingestion runs through the EG client. |
| `SDK-CONNECTOR-CONTROL-R012` | **Connector batch P-S migrates fully onto the SDK client.** Connector packages in the P-S range, including the repository-manager package's own agent_utilities imports, import agent_connector_sdk modules for server construction, configuration, exceptions, and transport security instead, and call the generated EG client instead of a local ingestion helper. | A per-package import scan and test run across the P-S batch confirming no agent_utilities import remains and ingestion runs through the EG client. |
| `SDK-CONNECTOR-CONTROL-R013` | **Connector batch T-Z migrates fully onto the SDK client.** Connector packages in the T-Z range import agent_connector_sdk modules in place of their prior agent_utilities imports and call the generated EG client instead of a local ingestion helper, and the shared package-builder templates used to scaffold every batch are retargeted onto the SDK as well. | A per-package import scan and test run across the T-Z batch and the scaffolding templates confirming no agent_utilities import remains. |
| `SDK-CONNECTOR-CONTROL-R014` | **SDK fully supersedes the duplicated connector toolkit.** Once every connector package imports the SDK's equivalents, the duplicated connector toolkit (server factory, action dispatch, concurrency, transport security, credentials, and related helpers) kept elsewhere becomes safe to delete, with no compatibility alias retained. Rollup: delivered once the fleet-wide census (R014.1) reports every connector migrated. | Tests confirming the SDK modules provide complete replacements for each listed toolkit area, plus a cross-repository import scan showing no connector still depends on the superseded implementation. |
| `SDK-CONNECTOR-CONTROL-R014.1` | **One reusable cross-repository import-scan call site.** `scan_many_packages` scans several connector package roots in one call and keys each result by package name, so R014's fleet-wide census, and every per-batch requirement (R009-R013), share one scan implementation instead of each re-deriving a loop over `scan_for_agent_utilities_imports`. | A test scans a mix of migrated and unmigrated synthetic package roots and confirms each is reported correctly, keyed by name. |
| `SDK-CONNECTOR-CONTROL-R015` | **SDK is sole owner of connector source lifecycle and certification.** Connector manifest parsing, live-contract validation, tool-schema normalization, artifact and pack construction, and certification live only in the SDK's manifest and certify packages; equivalent logic kept in a duplicate location is retired, and other consumers import the SDK packages directly instead of maintaining a parallel schema or publisher. Rollup: delivered once the real fleet-wide scan (R015.1) reports no dependent repository defines its own copy. | An import scan across dependent repositories confirming manifest and certification logic is sourced only from the SDK packages, plus certification conformance tests passing unchanged after the cutover. |
| `SDK-CONNECTOR-CONTROL-R015.1` | **A duplicate-definition scan for the manifest/certify surface.** `scan_for_duplicate_manifest_or_certify_definitions` flags a connector package that locally defines `ConnectorManifest`, `CertificationReport` or `certify_connector` itself rather than importing them from the SDK, distinguishing that from a plain mention in a string, comment or import. | A test proves an importing package is clean, a locally defined class or function is caught, a string/comment mention is not a false positive, and an unparsable file is skipped rather than fabricated clean. |
| `SDK-CONNECTOR-CONTROL-R016` | **Connector base settings live in the SDK's own config module.** Connector base settings previously defined in a shared configuration module move into the SDK's own config module; hosting and deployment settings and agent and model settings remain with their respective owning repositories rather than the SDK. | Configuration-loading tests confirming connector packages read base settings from the SDK's config module and that no connector depends on the removed shared module. |
| `SDK-CONNECTOR-CONTROL-R017` | **Every connector uses the shared TLS profile, no bare verify bypass.** Every connector package performs HTTPS calls through the SDK's shared TLS profile; no connector disables certificate verification with a bare boolean flag or silences the underlying TLS warning library, so unauthenticated TLS cannot pass unnoticed. | A static scan across connector packages for bare verify-disabling flags and suppressed TLS warnings, plus a negative test asserting such a bypass is rejected. |
| `SDK-CONNECTOR-CONTROL-R018` | **SDK source and test suite build cleanly from a fresh checkout.** The SDK's full test suite, strict type checking, and documentation build pass cleanly against the connector control implementation from a fresh checkout, with no partial or broken module left in the merged source tree. | A full test run, strict type check, and documentation build executed in continuous integration against the merged source. |
| `SDK-CONNECTOR-CONTROL-R019` | **Host servers register ontology resources without duplicate skills or prompts.** `ontology_resources` and `register_ontology_resources` build `ontology://<connector>/<file>.ttl` and `shapes://<connector>/<file>.ttl` resources from one ontology directory. `register_connector_content` reuses the same builder. A missing directory yields no resources. | MCP client tests list and read the resources, prove that no prompt registers, and prove the empty result for a missing directory. |
| `SDK-CONNECTOR-CONTROL-R020` | **One condensed intent contract: `MCP_TOOL_MODE` retired.** `register_tool_surface` always registers the condensed, action-routed tool surface, each tool tagged `gated`; no `MCP_TOOL_MODE` setting, mode branch, or separate verbose 1:1 tool surface remains in the SDK, matching agent-utilities' one condensed intent contract (agent-utilities#54). | Tests asserting `register_tool_surface` registers and gates condensed tools with no mode parameter, and a repository-wide scan confirming no `tool_mode`/`MCP_TOOL_MODE`/verbose-tool-surface module or reference remains. |
| `SDK-CONNECTOR-CONTROL-R021` | **Connector ontologies declare access contracts for virtual reads.** A connector ontology declares one `ac:AccessContract` per class it answers live. The contract names the access kind, the operation, its parameters, pagination and pushdown operations. It also names an auth reference, a rate limit, and freshness and cost hints. `parse_access_contracts` returns typed contracts whose fields match the agent-utilities `VirtualMapping` fields. The parser refuses a literal secret, an unknown pushdown operation and a missing operation. The vocabulary ships as `agent_connector_sdk/ontology/access_contract.ttl`. | CC-11 parses a fake connector ontology into a typed contract. It proves each refusal and proves that no secret text reaches an error. |
| `SDK-CONNECTOR-CONTROL-R022` | **The pack builder scopes `owl:imports` to the pack.** `build_content_pack` removes each ontology `owl:imports` that names no ontology entry of the same pack. It records each removed IRI as `ontology-import:<iri>` in that entry's `requires_capabilities` annotation. It handles Turtle and RDF/XML. A body without external imports stays byte-identical. | CC-12 tests removal, recording, mixed lists, lone statements, RDF/XML, self imports and determinism. |
| `SDK-CONNECTOR-CONTROL-R023` | **A prompt with a required argument is captured as a template, never refused.** `PromptArtifactKind` binds each required prompt argument to a deterministic `{{name}}` placeholder, calls `prompts/get` with those bindings, and records `capture.kind` as `template` with `capture.bound_arguments` as the placeholder map. A prompt with no required argument still captures as a `rendered` call with an empty binding map. | CC-13 captures a prompt with one required and one optional argument, asserts the placeholder binding reaches `prompts/get`, and asserts the stored `capture` metadata and successful `validate`. |
| `SDK-CONNECTOR-CONTROL-R024` | **A prompt the server rejects for its bound placeholder still captures as a template.** A typed required argument (`int`, `float`, `bool`, `list`, or an enum) can refuse the string `{{name}}` placeholder `prompts/get` sends for it. `McpClientSession.get_prompt` raises `McpPromptRejectedError` only for a well-formed MCP protocol error, never for a transport failure. `PromptArtifactKind.list_entries` catches `McpPromptRejectedError` for a prompt with at least one required argument and captures a deterministic template from the listed definition alone, with no rendered server content. A prompt with no required argument, or any failure that is not a protocol-level rejection, still raises. | CC-14 simulates a required typed argument raising `McpPromptRejectedError` from `prompts/get` and asserts the capture still succeeds as a `template` with no server-rendered text; a second case with no required argument asserts the same error still raises; a third case asserts a plain `McpTransportError` (a transport failure) always raises. |
| `SDK-CONNECTOR-CONTROL-R025` | **SDK provides identity-scoped resource entitlement resolution.** `agent_connector_sdk.entitlements` resolves which backend resources (kube contexts, SSH hosts, database connections, mounts) a caller's roles and groups entitle, generalizing "what may I do" to "what may I reach" over `agent_connector_sdk.identity.ActorContext`, so a connector auto-loads only the resources its caller's identity grants without importing `agent_utilities.security.entitlements`. A caller with no matching capability resolves an empty set; an unauthenticated or tenant-less actor is rejected before any resource catalog is exposed. | Tests prove a namespaced capability, a namespace wildcard, a bare zero-config capability, and a super-capability (`admin`/`system`) each resolve the documented entitled subset against a fake available-resource catalog, that no matching capability resolves empty, and that an unauthenticated or tenant-less actor raises before a catalog is read. |
| `SDK-CONNECTOR-CONTROL-R026` | **SDK provides opt-in per-client-method MCP tool derivation.** `agent_connector_sdk.mcp.method_tools.register_method_tools` registers one directly invocable, `params_json`-dispatched tool per public method of a connector's API-client class, named `<prefix>_<method>` with no doubled prefix, tagged by a domain derived from the method's defining class, for a connector whose served tool surface genuinely depends on that one-tool-per-method derivation instead of only the condensed intent contract (SDK-CONNECTOR-CONTROL-R020 retired the implicit, env-toggled verbose surface; this is an explicit opt-in primitive, not its return). A method classified destructive is gated behind a live caller's confirmation before it dispatches. A method defined only on a base-infrastructure class (auth, pagination, retry) is excluded. | Tests prove one tool registers per public client-class method across two domain classes with no doubled prefix, that a base-infrastructure method is excluded, that a destructive method is confirmed before it calls the client, that a declined or unattended confirmation never dispatches, and that an asynchronous `get_client` is awaited. |
| `SDK-CONNECTOR-CONTROL-R027` | **SDK resolves the selected provider-runtime profile for a multi-backend connector.** `resolve_selected_provider_runtime_profile` reads a connector's configured provider identifier and returns the matching runtime profile (base URL, auth mode, capability flags) from its registered profile set, rejecting an unconfigured or unknown provider before any request is attempted, for connectors that support more than one backend implementation (audiobookshelf-mcp, pulselink-mcp, fan-manager, vector-mcp). | Unit tests selecting a known profile by identifier, asserting an unknown identifier raises before any network call, and asserting the returned profile's fields reach the client that constructs requests. |
| `SDK-CONNECTOR-CONTROL-R028` | **SDK's governed HTTP client controls egress with named escape hatches, not ad hoc trust.** `create_http_client` builds an outbound client whose destination is checked against an SSRF policy, with explicit `pin_egress`, `allowed_private_hosts`, and `allow_loopback` parameters, and `pinned_egress_transport` returns a transport pinned to a resolved, policy-checked address so a later DNS change cannot redirect an already-approved request, for connectors that call self-hosted or private-network targets (vaultwarden-mcp, gitlab-api, pulselink-mcp). | Unit tests asserting a disallowed private or loopback destination is rejected by default, an explicitly allowed private host or loopback passes, and a pinned transport reuses the originally resolved address rather than re-resolving DNS. |
| `SDK-CONNECTOR-CONTROL-R029` | **SDK exposes a structured configuration singleton, not only a flat `setting()` lookup.** An `AgentConfig` object groups related settings into named sections (auth, transport, limits) with typed fields and validation at construction, and is accessible as a process-wide singleton so a connector reads validated structured configuration instead of re-parsing individual `setting()` calls at each use site, for connectors with more than a handful of interrelated settings (vector-mcp, systems-manager, repository-manager). | Unit tests constructing `AgentConfig` from environment input, asserting invalid combinations fail at construction, and asserting the singleton accessor returns the same validated instance across call sites. |
| `SDK-CONNECTOR-CONTROL-R030` | **SDK provides GraphQL introspection context helpers for connector tools.** `ctx_graphql_list_types` and `ctx_graphql_get_type_details` let a tool resolve a GraphQL schema's declared types and a named type's fields and arguments from the connector's own session context, without the tool hand-rolling an introspection query, for connectors whose backend is GraphQL-native (leanix-agent, twenty-mcp). | Unit tests against a fake GraphQL schema asserting `ctx_graphql_list_types` lists the declared types and `ctx_graphql_get_type_details` returns a named type's fields and argument shapes, including a not-found case for an unknown type name. |
| `SDK-CONNECTOR-CONTROL-R031` | **SDK's client-credentials token provider accepts a literal client secret, matching the signature connectors already call.** `ClientCredentialsTokenProvider` accepts a literal `client_secret` string argument, in addition to any credential-reference form, so a connector migrating from its prior client-credentials helper keeps the same construction call shape, for connectors using OAuth2 client-credentials against an identity provider (keycloak-agent, gitlab-api). | A signature-compatibility test constructing `ClientCredentialsTokenProvider` with a literal `client_secret` string and asserting a token fetch call is made with that secret, plus a negative test asserting the secret is never logged or serialized. |
| `SDK-CONNECTOR-CONTROL-R032` | **SDK provides opt-in verbose, one-tool-per-method surface derivation via `register_tool_surface`.** Beyond the condensed intent contract (SDK-CONNECTOR-CONTROL-R020), `register_tool_surface` can derive and register a verbose, per-method tool surface for a connector whose callers depend on individually named tools rather than the condensed action-routed surface, for connectors still migrating their serving surface off a verbose predecessor (data-science-mcp, vector-mcp, twenty-mcp). | Tests asserting `register_tool_surface` in verbose mode registers one tool per targeted method with no doubled prefix, and that the condensed surface remains available and unaffected when verbose derivation is also requested. |
| `SDK-CONNECTOR-CONTROL-R033` | **SDK's governed HTTP layer provides a `safe_post_json` helper with the same private-host allowance as its GET path.** `safe_post_json` performs a JSON POST through the SSRF-checked client, accepting `allowed_private_hosts` so a connector that must POST to an explicitly allowed private or self-hosted endpoint does not have to drop to an unchecked client, for connectors that submit data rather than only read it (audiobookshelf-mcp, pulselink-mcp, data-science-mcp). | Unit tests asserting a disallowed destination is rejected before the POST is sent, an allowed private host succeeds and returns parsed JSON, and a non-JSON response surfaces a typed error rather than a raw parse exception. |
| `SDK-CONNECTOR-CONTROL-R034` | **SDK provides shared library-file-path resolution and cross-process file locking utilities.** `get_library_file_path` resolves a connector's on-disk library or state file path from configuration in one place, and `file_lock` provides a cross-process advisory lock around a read-modify-write of that file, for connectors that persist local state or library data outside the graph (systems-manager, fan-manager, repository-manager). | Unit tests asserting `get_library_file_path` resolves a consistent path from configuration, and a concurrency test asserting `file_lock` serializes two simulated writers so neither observes a partially written file. |
| `SDK-CONNECTOR-CONTROL-R035` | **SDK provides a CredentialProvider/SecretsClient abstraction for connectors, not only a credential-reference string.** A `CredentialProvider` (or `SecretsClient`) resolves an `env://` or `openbao://` reference to its secret value on demand, scoped to the requesting connector's identity, and never returns or logs the resolved value in a reusable form, for connectors with multiple credential-bearing calls per request (vaultwarden-mcp, keycloak-agent, repository-manager). | Unit tests asserting resolution for both reference schemes, a denial for a reference outside the caller's scope, and a logging-inspection test asserting no resolved secret value appears in any log record. |
| `SDK-CONNECTOR-CONTROL-R036` | **SDK's identity-scoped resource entitlements cover the backend-resource catalogs these connectors manage.** Building on SDK-CONNECTOR-CONTROL-R025's entitlement resolution, `agent_connector_sdk.entitlements` resolves identity-scoped resource entitlements against the specific backend-resource catalogs these connectors expose (keycloak-agent realms and clients, systems-manager managed hosts, vaultwarden-mcp vaults and collections), so each connector auto-loads only the resources its caller's identity grants without importing `agent_utilities.security.entitlements`. | Tests proving a caller's resolved entitlement set against each connector's own resource catalog shape, that an unmatched capability resolves empty, and that no connector still imports `agent_utilities.security.entitlements`. |
