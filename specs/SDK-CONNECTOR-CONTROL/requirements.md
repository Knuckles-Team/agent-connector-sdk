# SDK-CONNECTOR-CONTROL requirements

| ID | Requirement | Verification |
|---|---|---|
| `SDK-CONNECTOR-CONTROL-R001` | **ConnectorPackClient uses a deterministic idempotency key.** The SDK's ConnectorPackClient submits pack publication requests through the generated ConnectorPack types and computes a deterministic idempotency key from tenant, connector identity, canonical pack digest, and operation, so repeating an identical request returns the same durable result. | Unit tests that retry an identical publish request after a simulated transport loss and assert the same import operation key is reused, using only the generated wire types for status and import. |
| `SDK-CONNECTOR-CONTROL-R002` | **Contract pin travels as a claim attribute, not recomputed downstream.** The SDK computes the contract pin by normalizing tool input and output schemas through manifest/tool_schema.py and passes it to the graph service as a claim attribute; the graph service stores that value without independently recomputing the SDK's schema normalization. | Conformance tests asserting the pin calculation lives in the SDK and that a stored claim attribute matches the SDK-computed value unchanged. |
| `SDK-CONNECTOR-CONTROL-R003` | **Canonical output-schema digest on every certified tool pin.** Certification computes a normalized output-schema digest for every tool pin alongside the input-schema digest, fingerprinting a missing output schema canonically rather than treating it as an empty wildcard. | A conformance test that certifies a tool with no declared output schema and asserts a canonical, nonempty digest is produced. |
| `SDK-CONNECTOR-CONTROL-R004` | **Contract-pin verification owned by the SDK's own test kit.** The SDK's own conformance test kit computes and checks the contract pin from its tool schema normalization, because that normalization is SDK-specific logic the graph service cannot reproduce independently. | A conformance suite that recomputes the contract pin from a sample manifest and asserts it matches the certified value. |
| `SDK-CONNECTOR-CONTROL-R005` | **Pack publisher and source submission use generated graph-client types.** The SDK's pack publisher uses the graph service's generated ConnectorPack and AgentComponent.Content request and response types instead of a hand-written placeholder content pack, and SQL-backed source record submission uses the generated SourceIngest request and receipt types through the existing sink. | Integration tests that publish a pack and submit a source record through the generated types and assert no placeholder or hand-written duplicate type is used. |
| `SDK-CONNECTOR-CONTROL-R006` | **Decision-service proposals for tool choice and triage stay observational.** Connector-internal tool choice and inbound event triage may request a proposal from a decision service, but that proposal is observational only: it never directly authorizes a side effect or bypasses the deterministic write-back rules. | A contract test that issues a decision-service proposal and asserts no side effect is authorized without passing through the deterministic write-back path. |
| `SDK-CONNECTOR-CONTROL-R007` | **Fleet-wide re-certification yields nonempty schema fingerprints.** Re-certifying the connector fleet means every package produces current, nonempty fingerprints for each declared tool pin and passes a current live-contract comparison; a package count alone is not sufficient evidence of certification. | A certification run across the full connector set asserting every pin's input and output schema fingerprint is nonempty and matches a live contract comparison. |
| `SDK-CONNECTOR-CONTROL-R008` | **Closed, canonical pack annotation map across the connector fleet.** Every connector pack entry carries a closed, canonical annotation map of capability names, input and output schema digests, modality, and bounded cost and latency estimates with units; a missing estimate is recorded as unknown, never zero. | Conformance tests that validate the annotation map's types and units and assert a semantic annotation change shifts the pack digest. |
| `SDK-CONNECTOR-CONTROL-R009` | **Connector batch A-E migrates fully onto the SDK client.** Connector packages in the A-E range import agent_connector_sdk modules for server construction, configuration, exceptions, and transport security in place of their prior agent_utilities imports, and call the generated EG client instead of a local ingestion helper. | A per-package import scan and test run across the A-E batch confirming no agent_utilities import remains and ingestion runs through the EG client. |
| `SDK-CONNECTOR-CONTROL-R010` | **Connector batch F-J migrates fully onto the SDK client.** Connector packages in the F-J range import agent_connector_sdk modules for server construction, configuration, exceptions, and transport security in place of their prior agent_utilities imports, and call the generated EG client instead of a local ingestion helper. | A per-package import scan and test run across the F-J batch confirming no agent_utilities import remains and ingestion runs through the EG client. |
| `SDK-CONNECTOR-CONTROL-R011` | **Connector batch K-O migrates fully onto the SDK client.** Connector packages in the K-O range import agent_connector_sdk modules for server construction, configuration, exceptions, and transport security in place of their prior agent_utilities imports, and call the generated EG client instead of a local ingestion helper. | A per-package import scan and test run across the K-O batch confirming no agent_utilities import remains and ingestion runs through the EG client. |
| `SDK-CONNECTOR-CONTROL-R012` | **Connector batch P-S migrates fully onto the SDK client.** Connector packages in the P-S range, including the repository-manager package's own agent_utilities imports, import agent_connector_sdk modules for server construction, configuration, exceptions, and transport security instead, and call the generated EG client instead of a local ingestion helper. | A per-package import scan and test run across the P-S batch confirming no agent_utilities import remains and ingestion runs through the EG client. |
| `SDK-CONNECTOR-CONTROL-R013` | **Connector batch T-Z migrates fully onto the SDK client.** Connector packages in the T-Z range import agent_connector_sdk modules in place of their prior agent_utilities imports and call the generated EG client instead of a local ingestion helper, and the shared package-builder templates used to scaffold every batch are retargeted onto the SDK as well. | A per-package import scan and test run across the T-Z batch and the scaffolding templates confirming no agent_utilities import remains. |
| `SDK-CONNECTOR-CONTROL-R014` | **SDK fully supersedes the duplicated connector toolkit.** Once every connector package imports the SDK's equivalents, the duplicated connector toolkit (server factory, action dispatch, concurrency, transport security, credentials, and related helpers) kept elsewhere becomes safe to delete, with no compatibility alias retained. | Tests confirming the SDK modules provide complete replacements for each listed toolkit area, plus a cross-repository import scan showing no connector still depends on the superseded implementation. |
| `SDK-CONNECTOR-CONTROL-R015` | **SDK is sole owner of connector source lifecycle and certification.** Connector manifest parsing, live-contract validation, tool-schema normalization, artifact and pack construction, and certification live only in the SDK's manifest and certify packages; equivalent logic kept in a duplicate location is retired, and other consumers import the SDK packages directly instead of maintaining a parallel schema or publisher. | An import scan across dependent repositories confirming manifest and certification logic is sourced only from the SDK packages, plus certification conformance tests passing unchanged after the cutover. |
| `SDK-CONNECTOR-CONTROL-R016` | **Connector base settings live in the SDK's own config module.** Connector base settings previously defined in a shared configuration module move into the SDK's own config module; hosting and deployment settings and agent and model settings remain with their respective owning repositories rather than the SDK. | Configuration-loading tests confirming connector packages read base settings from the SDK's config module and that no connector depends on the removed shared module. |
| `SDK-CONNECTOR-CONTROL-R017` | **Every connector uses the shared TLS profile, no bare verify bypass.** Every connector package performs HTTPS calls through the SDK's shared TLS profile; no connector disables certificate verification with a bare boolean flag or silences the underlying TLS warning library, so unauthenticated TLS cannot pass unnoticed. | A static scan across connector packages for bare verify-disabling flags and suppressed TLS warnings, plus a negative test asserting such a bypass is rejected. |
| `SDK-CONNECTOR-CONTROL-R018` | **SDK source and test suite build cleanly from a fresh checkout.** The SDK's full test suite, strict type checking, and documentation build pass cleanly against the connector control implementation from a fresh checkout, with no partial or broken module left in the merged source tree. | A full test run, strict type check, and documentation build executed in continuous integration against the merged source. |
| `SDK-CONNECTOR-CONTROL-R019` | **Host servers register ontology resources without duplicate skills or prompts.** `ontology_resources` and `register_ontology_resources` build `ontology://<connector>/<file>.ttl` and `shapes://<connector>/<file>.ttl` resources from one ontology directory. `register_connector_content` reuses the same builder. A missing directory yields no resources. | MCP client tests list and read the resources, prove that no prompt registers, and prove the empty result for a missing directory. |
