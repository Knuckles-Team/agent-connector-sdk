# SDK-CENTRALIZED-CAPABILITIES — Requirements

Governing spec: [spec.md](spec.md).

Each row is one centralized capability. A child row `.n` is one five-minute unit of work. A row names the module it covers and the check that proves it. The generator sets each row's state in `status.json`.

| `SDK-CENTRALIZED-CAPABILITIES-R004` | **Pagination helpers.** Connectors page upstream lists with the SDK pagination helpers. The helpers cover the `cursor`, `page`, `offset`, `link`, `since_id`, and `next_url` modes. The `next_url` mode follows the next-page URL at a dotted body path, `next` by default. It resolves a relative URL against the request URL and stops on a null or empty value. Each followed URL must keep the scheme, host, and port of the first request. A mismatch raises `PaginationOriginError` and the helper does not follow it. A repeated URL ends the sweep and sets `truncated`. The `max_pages` cap also ends it. A connector must not ship its own page-walking loop for a mode the SDK covers. Owner: this spec. | `SDK-CENTRALIZED-CAPABILITIES-R004.1` | **Refuse unsafe next-page URLs without exposing credentials.** The `next_url` mode refuses userinfo in its first or next URL. It also refuses malformed origins. It raises `PaginationOriginError` before fetching an unsafe URL. Refusal details contain no URL or credential. | Sync and async pagination tests cover same-origin userinfo, cross-origin userinfo, and malformed ports without exposing credentials. |
| `SDK-CENTRALIZED-CAPABILITIES-R004.2` | **Link pagination stays on the admitted origin.** Link mode requires an absolute endpoint or `base_url`. It resolves each next link against the current URL. A repeated link ends the sweep. | Sync and async tests cover same-origin links, cross-origin and userinfo refusals, missing base, and loop termination. |
